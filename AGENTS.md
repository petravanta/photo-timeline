# Notes for coding agents

Follow the shared standards in https://github.com/petravanta/general/blob/main/STANDARDS.md (hub link, theme switch, shared look, user data). Take patterns from there, not from the other apps. This file only adds what's specific to Photo Timeline.

- The app is `index.html` with no build step. Serve the folder (`python3 -m http.server`) to run it.
- There is no built-in knowledge, so there is no `data/` folder. If the app ever ships presets (track or band templates, say), they go in `data/` as the standards describe.
- The timeline is one canvas drawn by `draw()`. The screen and the saved image both go through it, so change it once and both follow. `layout()` decides where everything goes and knows nothing about scrolling; the screen canvas is only as wide as the view and redraws on scroll, which keeps it inside Safari's canvas size limit.
- Colors on the canvas come from CSS tokens (`--c-<color>` for the picker colors) read by `readTokens()`, and redraw when `data-theme` changes. Add a color by adding its token in all three theme blocks and its key to `COLORS`. A timeline's `style` (`STYLES`: vivid, elegant, mono) sets `data-style` on the root: its colors are CSS blocks that override the `--c-<color>` tokens (again in all three theme blocks, six-digit hex so `rgba()` can read them), and its line weights, corners and title font are in `STYLES`.
- The document (`photoTimeline.data` in `localStorage`) follows the standards' *User data* shape: `timelines`, `tracks`, `photos`, `bands` and `events` records with `id` and `u`, and `deleted`. Every record but a timeline names its `timeline`; a timeline record holds its name and display settings. `copyTimeline()` duplicates every record of a timeline under new ids, photo files included, so the two never share anything. Read the open timeline's records with `mine(kind)` and the timeline itself with `cur()`. Which timeline is open is kept per device under `photoTimeline.current`, outside the document. `upgrade()` turns a version 1 document (one timeline, display settings in `settings`) into version 2. A timeline's `refs` lists its named reference dates (`{id, name, from, as}`); each photo gets a line per ref from `refLines()` (only the latest one already passed when `refLatest` is on), and `upgrade()` turns the old single `ageFrom`/`ageAs` into one ref. Photo files live in IndexedDB (`photo-timeline` / `images`), keyed by photo id; a backup carries them as data URLs under `images`.
- Google Photos goes through the Photos Picker API only (the Library API can no longer read a person's library): open a session, send the person to its `pickerUri`, poll until `mediaItemsSet`, list the items, download each `baseUrl` with the bearer token, then delete the session. `createTime` is UTC and becomes the photo's local date. Photos keep `from: 'google'`.
- Dates are local wall-clock strings, as cameras record them: photos `YYYY-MM-DDTHH:MM:SS`, bands and events `YYYY-MM-DD` (a band's `end` day is included). A band with `ongoing: true` runs to today: read its last day with `lastDay(b)`, never `b.end`, which only holds the end to fall back to when it's switched off. Parse them with `parseLocal()`, never `new Date(string)`, which reads a bare date as UTC.
- The playthrough video (`playModel()` / `playFrame()`) is drawn frame by frame, so the preview, full screen and the saved video share it. Saving encodes with WebCodecs off screen, faster than real time, and builds the MP4 with `mp4-muxer` loaded from jsDelivr on first use; browsers without WebCodecs record the canvas with `MediaRecorder` in real time instead.
- Google Drive sync (`driveSync()`) uses the `drive.file` scope and a "Photo Timeline" folder: `Photo Timeline data.json` (the document, merged with `mergeDocs()`) and one JPEG per photo, found by `appProperties` (`pt: folder | data | photo`, `pid` for the photo id). It runs a few seconds after each save, on load and when the page comes back into view. Google's sign-in is a pop-up, so a sync nobody tapped for only runs while the last token lasts. The token is shared with the other apps through `GoogleToken` (general/shared/google-token.js, inlined); any tap renews it in its last ten minutes, and otherwise a Reconnect Drive button appears.
